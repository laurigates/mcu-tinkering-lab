# Move or rename a project

From the robocar re-home (#1142): `packages/robocar/unified` became
`packages/robotics/robocar`, four siblings nested inside it, and
`robocar-unified` became `robocar`. 805 files changed. A `git mv` plus a text
sweep left `just` unable to parse, the firmware polling a 404 for OTA, and
both carrier schematics stale, with most of CI green.

## Order of work

1. **Move with `git mv`**, then delete the ignored build trees that travelled
   with the directory (`build-host/`, `twin/build/`, `.venv/`): their CMake
   caches and editable `.pth` files name the old path, and the host suites
   refuse to configure until they are gone.
2. **Sweep with anchored rules, longest prefix first.** Never use a bare
   `packages/<domain>/` prefix rule: at #1142 that prefix also named the
   removed dual-board directories (`packages/robocar/main`, `/camera`) in 57
   lines of ADRs and test fixtures. Exclude every `CHANGELOG.md` and `*.kicad_sch`, and keep
   the old identifier on any line naming a published release
   (`<old>-v<digit>`).
3. **Fix what the sweep cannot see** (table below).
4. **Regenerate**, in this order: schematics, board relink, `pin_defs.typ`,
   the Typst PDFs.
5. **Run `just --list --list-submodules` first and last.** One unresolved
   import in any module makes every recipe in the repo fail, and CI never
   parses a justfile except through `tools/check-flash-recipes.py`.

## What a path or identifier sweep does not reach

| Thing | Why | What to do |
|---|---|---|
| Carrier schematics | Every UUID is `uuid5` of the repo-relative carrier directory (`tools/kicad/schematic.py`). A move changes them all, and the board's footprint `(path ...)` links with them | `PYTHONPATH=tools python3 -m kicad.schematic <projects>`, then `PYTHONPATH=tools python3 -m kicad.boardcheck --relink <projects>`. Relink changes only the path lines. Do not re-route |
| Check stamps | They hash the `.kicad_sch` and `.kicad_pcb` bytes | Only `just <project>::carrier-check` with local KiCad may rewrite them. `carrier-check.yml` is red until then; say so in the PR |
| KiCad lib tables | `${KIPRJMOD}/../…` depth to `tools/kicad/lib` | Regenerated by `kicad.schematic`; never sed them |
| Pages firmware directory | `firmware/<basename of the flasher.json directory>`. The firmware's `OTA_MANIFEST_URL` hardcodes it | Edit the URL. `tools/check-ota-consumer-agreement.py` compares it with the directory |
| `.github/project-matrix.json` | `path` and `extra_paths` are relative to `packages/`, so they carry no `packages/` prefix | Edit by hand; `tools/check-component-extra-paths.py` checks them |
| Paths built from parts, and globs | `REPO / "packages" / "x" / "y"`, `packages/x/**`, `packages/*/*/…` | `git grep` for the split forms after the sweep. Two-segment globs miss a nested project without an error (`kicad.lcsc` dropped the integrated carrier) |
| Relative paths | `../../../tools/…` from a justfile, `../sibling/main` in CMake, Markdown links | Resolve each on disk from the file's directory; do not count dots |
| The schematic PNG | Not byte-reproducible across hosts, and the PDFs embed it | `git mv` only. Do not run `hardware::gen` or `schematics::render-all` |
| Typst PDFs | Rendered text carries the names; CI byte-compares with Typst 0.15.0 | Recompile last. Control first: recompile an unaffected PDF and require identical bytes |

## Nesting a project inside another

A subproject sits one level deeper (`packages/<domain>/<project>/<sub>/`):

- Its justfile imports `../../../../tools/…`. `tools/esp32.just` builds the
  compose path from its own location, so depth does not matter there;
  `tools/pico.just` still assumes depth 3.
- The outer project's CI entry and release package now contain it. Add it to
  the outer entry's `exclude_paths` in `project-matrix.json` and to the
  package's `exclude-paths` in `release-please-config.json`. release-please's
  entries are repo-root-relative; a package-relative one excludes nothing and
  warns about nothing. `tools/check-component-extra-paths.py` fails when a
  nested project is missing from either list.
- Without the excludes, a commit to the subproject rebuilds the outer
  firmware and, for a `feat`/`fix`, releases it.
- The outer project's `CLAUDE.md`, `.clangd` and `.gitignore` now apply to
  the subproject. `hardware.docs` scans its Markdown unless it has its own
  `hardware.toml`.

## Renaming a release component

- Rename the `release-please-config.json` key and the
  `.release-please-manifest.json` key in one commit and leave the versions
  alone. With only one renamed, the manifest generator falls back to the tag
  string as the version.
- release-please finds no previous release under the new name. It takes the
  version from the manifest, so the next version is still right, but the
  first changelog compare link points at a tag that does not exist.
- The commit type decides what releases at merge. A `refactor` releases
  nothing; any listed type releases every package whose files the commit
  touched.
- Tags and assets under the old name stay. `just <project>::flash <old ref>`
  and the GlitchTip ELF lookup cannot reach them; say so where they are
  documented, and do not invent a tag or asset name for an old version.
- The Pages directory, the OTA notify topic (`<component>/ota/notify`) and
  the Improv device name all change. A fielded device polls the old manifest
  URL; `build-firmware.yml` kept an alias at `firmware/unified` for one hop
  (#1137). The web flasher offers an erasing Install when the Improv name
  differs, so reflash over USB with the just recipe.

## Committing

- The `check-credentials` hook matches `credentials\.h` unanchored, so a
  rename of `main/credentials.h.example` blocks the commit. Confirm it is the
  only staged match, then commit with `SKIP=check-credentials`.
- One squash-merged commit. A separate pure-move commit leaves a commit on
  `main` whose justfiles do not parse.
- Other checkouts keep their ignored files in the old directory.
  `main/credentials.h` must be moved by hand before the next build, or CMake
  writes a stub with no broker URI (#1138).

## Not verified by anything in CI

Read these before calling a move done: the firmware build of the moved
project (first compile of its new `project()` name and any changed
`EXTRA_COMPONENT_DIRS`), `just --list`, the two KiCad stamps, dead Markdown
links (the repo has no link check), and release-please's reading of the new
paths, which shows only in the first release PR after the merge.
